## 摘要
低推力轨迹优化是深空任务设计的核心技术。基于庞特里亚金极小值原理(PMP)的间接方法提供了严格的优性保证，但其实际应用面临三个瓶颈：(1)横截条件必须针对每种约束类型逐例推导；(2)不同的动力学模型需要重复编写代码；(3)打靶方程对初值猜测高度敏感。本文提出HELIOS(低推力行星际优化系统启发式引擎)，一种围绕大型语言模型(LLM)构建的轨迹优化代理。给定用自然语言描述的物理问题，系统自主执行PMP符号推导、SymPy验证、C++打靶代码生成和数值求解，无需人工干预。关键创新包括：(1)约束自适应推导框架，将任意约束统一为psi(x,p)=0形式，并自动生成自由参数(如引力辅助转角)的平稳条件；(2)动力学自适应四模块代码生成，支持非标准动力学(太阳帆、J2摄动)而无需修改底层模板；(3)覆盖PMP推导中关键易错点的通用推导规则集。在11个渐进式测试场景上的实验表明，HELIOS能正确推导并求解从简单交会(8个变量)到多段驻留转移(48个变量)、引力辅助轨迹(17个变量)以及太阳帆最小时间转移(8个变量)的问题。最佳编译成功率达100%(11/11)。多模型对比(8个开源LLM后端，总分250-905)验证了模型无关架构，并揭示了模型规模与推导能力之间的正相关关系。

## Abstract
Low-thrust trajectory optimization is a core technology in deep-space mission design. Indirect methods based on Pontryagin's Minimum Principle (PMP) offer rigorous optimality guarantees, yet their practical application faces three bottlenecks: (1) transversality conditions must be derived case by case for each constraint type; (2) different dynamics models require repeated code rewrites; and (3) shooting equations are highly sensitive to initial guesses. This paper presents HELIOS (Heuristic Engine for Low-thrust Interplanetary Optimization System), a trajectory optimization agent built around a large language model (LLM). Given a physical problem described in natural language, the system autonomously performs PMP symbolic derivation, SymPy verification, C++ shooting-code generation, and numerical solution without human intervention. Key innovations include: (1) a constraint-adaptive derivation framework that unifies arbitrary constraints into psi(x,p)=0 form and automatically generates stationarity conditions for free parameters (e.g., gravity-assist turning angle); (2) dynamics-adaptive four-module code generation supporting non-standard dynamics (solar sail, J2 perturbation) without modifying the underlying template; and (3) a general derivation rule set covering critical error-prone points in PMP derivation. Experiments on 11 progressive test scenarios show that HELIOS correctly derives and solves problems from simple rendezvous (8 variables) to multi-leg stay transfers (48 variables), gravity-assist trajectories (17 variables), and solar-sail minimum-time transfers (8 variables). The best compilation success rate reaches 100% (11/11). A multi-model comparison (8 open-source LLM backends, total scores 250-905) verifies the model-agnostic architecture and reveals a positive correlation between model scale and derivation capability.

## 2. 方法论

### 2.1 核心设计原则
- 问题描述只陈述物理事实，不包含任何 PMP 推导结果；从极小值原理的原初形式出发，由 LLM 自主完成全部推导与代码生成，从而获得跨约束/动力学/目标的普遍适应性。

### 2.2 五阶段流水线架构（HELIOS 系统结构）
1. **约束解析**（ConstraintParser）：自然语言 → 结构化 JSON 问题规范（中心天体、出发/到达状态、航天器参数、动力学模型、约束列表、优化目标），统一以约束对象表示，不区分类型；
2. **PMP 推导**（PMPDeriver）：输出哈密顿量、协态微分方程 ∘、最优控制律（bang-bang 开关函数或光滑控制公式）、全部横截条件以及打靶变量/方程清单（一一对应）；验证失败可进入最多 3 轮精化循环；
3. **SymPy 符号验证**（SymPyVerifier）：以符号方式计算 −∂H/∂x 并与 LLM 推导结果对比；*对复杂动力学模型验证超时则跳过，直接进入代码生成*（advisory 模式，不阻塞流水线）；
4. **代码生成**（CodeGenerator）：将 PMP 推导结果翻译为 C++ 打靶代码，采用**固定模板 + LLM 生成模块**分离架构；每场景需生成 2 个（高轨标准低推力）或 4 个（非标准动力学，如太阳帆）模块；
5. **编译与求解**（SolverRunner）：g++ 编译 + cminpack hybrd1 求解，内含自适应 ε-同伦策略、随机重启、残差最小初值留存、ε 几何递减（0.05→0.01→0.001）；编译失败由 LLM 自动修复（最多 3 轮）。

### 2.3 关键技术框架
- **约束自适应统一推导框架**：将任意约束统一为 ψ(x, p1, p2, …) = 0 形式；分类为状态变量（A）、乘子（B）、自由参数（C）三类。每个内部约束乘子 ν 与每个自由参数 p 均成为打靶变量；相应生成约束方程 ψ=0、自由参数平稳方程 Σk νk·∂ψk/∂p = 0、自由时间横截条件 H(t⁻k) − H(t⁺k) − Σν·∂ψ/∂tk = 0。引力辅助中的转角 δ、方位角 ϕ、近心点半径 rp 均可自动识别为 Category C 参数，无需手工推导 GA 专用横截条件。
- **动力学自适应四模块代码生成**：DYNAMICS（标准低推力用模板默认 fmax/fmid/fnull，非标准动力学如太阳帆由 LLM 生成自定义右端项）/ SWITCH（模板默认 bang-bang 开关，或 LLM 生成控制律）/ RESIDUAL / SOLVE。该分离架构使系统在不改动底层模板的前提下支持 J2 摄动、太阳帆等动力学模型。
- **通用推导规则集**：
  - Rule 0：所有问题中的约束必须出现在打靶方程组中；
  - Rule B：内部点约束导致协态跳跃 λ⁺ = λ⁻ + νᵀ∂ψ/∂x；
  - Rule B2：自动扫描约束中的自由参数并生成平稳方程；
  - Rule G1：λ0 必须为打靶变量并纳入球面归一化；
  - Rule G2：最优控制方向必须显式验证符号约定；
  - Rule G3：当控制方向依赖状态（如帆法向依赖 ˆr）时，协态方程必须含几何导数 ∂n/∂x 项；
  - Rule G4：不出现在动力学方程中的变量（如太阳帆质量）不得作为状态变量。
- **数值稳定性技巧**：归一化单位（AU/年）、时间参数化为分数 τ∈[0,1]、到达历元实时评估、无需次级缩放的 m 量残差、显式声明 H 的极小/极大原理符号约定。

## 7. 优点

- **五阶段全自动流水线**：从自然语言到最优轨迹的端到端自动化，将传统数天的逐例手工推导压缩为分钟级流水线。
- **约束统一框架优雅有力**：把任意约束统一为 ψ(x,p)=0，通过类别 C 自由参数的自动识别和稳定条件生成，从根本上消解了间接法长期存在的“逐约束类型推导横截条件”痛点——这在低推力轨迹优化领域是原创性突破。
- **四模块代码生成架构设计严谨**：固定模板与 LLM 生成模块的分离使得系统可同时保证数值基础设施的可靠性（RK4、同伦、求解器接口）与非标准动力学的灵活性（太阳帆、J2 均验证可用）。
- **通用性规则集提炼**：G1–G4、B2 等规则是 PMP 理论的一般性知识而非面向特定问题的“作弊提示”，具有可移植价值。
- **多模型大规模对比实验**：8 个开源模型 × 11 场景的完整评分矩阵，选择开源模型以保障可复现性，评分维度涵盖流程各环节，对比设计相对客观、公平。
- **详实的案例剖析**：S07 场景完整展示了解析→推导→验证→生成→求解全链路的输入输出细节，极具教学与工程参考价值。

- **数值收敛维度受随机性污染**：收敛评价依赖纯随机初值，变量数 ≥17 的场景收敛概率衰减严重，使 d4 得分含机会成分，结论的可复现性和可比性受限；论文自述需系统研究物理信息初值构造、约化问题延续、近似解热启动等替代初始化策略。

- **多场景的数值正确性验证深度不齐**：仅 S07、S10 的收敛解经过与参考解的详细数值比对，其余场景的收敛质量验证强度不一。
- **LLM 输出非确定性与健壮性风险**：同一问题两次推理可能产生风格不同的代码，生产环境需增加后处理（如检查打靶方程线性无关性）。
- **通用能力门槛**：9B 级小模型（GLM-4-9B）完全无法完成任务，说明该方案对底层模型推理能力有硬性下限。
- **未涵盖的动力学/约束场景**：太阳光压、大气阻力、更高阶重力场、路径不等式约束的验证等仍是未探索方向。
- **算力资源信息缺失**：如第 4 节所述，论文未披露 GPU 等具体推理硬件配置，影响部署成本的精确估计与复现。
