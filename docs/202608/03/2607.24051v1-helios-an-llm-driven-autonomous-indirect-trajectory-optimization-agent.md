## 摘要
低推力轨迹优化是深空任务设计的核心技术。基于庞特里亚金极小值原理（PMP）的间接方法提供了严格的最优性保证，但其实际应用面临三个瓶颈：（1）横截条件必须针对每种约束类型逐例推导；（2）不同的动力学模型需要重复编写代码；（3）打靶方程对初始猜测高度敏感。本文提出了HELIOS（低推力行星际优化启发式引擎系统），一种围绕大语言模型（LLM）构建的轨迹优化智能体。给定用自然语言描述的物理问题，该系统无需人工干预即可自主执行PMP符号推导、SymPy验证、C++打靶代码生成和数值求解。关键创新包括：（1）约束自适应推导框架，将任意约束统一为psi(x,p)=0形式，并自动生成自由参数（如引力辅助转角）的平稳条件；（2）动力学自适应的四模块代码生成，支持非标准动力学（太阳帆、J2摄动）而无需修改底层模板；（3）一套涵盖PMP推导中关键易错点的通用推导规则集。在11个递进测试场景上的实验表明，HELIOS能够正确推导并解决从简单交会（8个变量）到多段停留转移（48个变量）、引力辅助轨迹（17个变量）和太阳帆最小时间转移（8个变量）等问题。最佳编译成功率可达100%（11/11）。多模型对比（8个开源LLM后端，总得分250-905）验证了模型无关的架构，并揭示了模型规模与推导能力之间的正相关性。

## Abstract
Low-thrust trajectory optimization is a core technology in deep-space mission design. Indirect methods based on Pontryagin's Minimum Principle (PMP) offer rigorous optimality guarantees, yet their practical application faces three bottlenecks: (1) transversality conditions must be derived case by case for each constraint type; (2) different dynamics models require repeated code rewrites; and (3) shooting equations are highly sensitive to initial guesses. This paper presents HELIOS (Heuristic Engine for Low-thrust Interplanetary Optimization System), a trajectory optimization agent built around a large language model (LLM). Given a physical problem described in natural language, the system autonomously performs PMP symbolic derivation, SymPy verification, C++ shooting-code generation, and numerical solution without human intervention. Key innovations include: (1) a constraint-adaptive derivation framework that unifies arbitrary constraints into psi(x,p)=0 form and automatically generates stationarity conditions for free parameters (e.g., gravity-assist turning angle); (2) dynamics-adaptive four-module code generation supporting non-standard dynamics (solar sail, J2 perturbation) without modifying the underlying template; and (3) a general derivation rule set covering critical error-prone points in PMP derivation. Experiments on 11 progressive test scenarios show that HELIOS correctly derives and solves problems from simple rendezvous (8 variables) to multi-leg stay transfers (48 variables), gravity-assist trajectories (17 variables), and solar-sail minimum-time transfers (8 variables). The best compilation success rate reaches 100% (11/11). A multi-model comparison (8 open-source LLM backends, total scores 250-905) verifies the model-agnostic architecture and reveals a positive correlation between model scale and derivation capability.

## 2. 论文提出的方法论

### 核心思想
- 问题描述仅包含物理事实，不包含任何 PMP 推导结果；系统从极小值原理的原始形式出发，由 LLM 自主完成推导、验证、代码生成与求解，实现跨约束类型、动力学模型和优化目标的通用适应性。

### 五阶段流水线架构
1. **约束解析**（ConstraintParser）：将自然语言问题解析为结构化 JSON（问题规格），统一表示所有约束，不区分类型。
2. **PMP 推导**（PMPDeriver）：核心智能模块，输出哈密顿量、协态微分方程、最优控制律、所有横截条件、打靶变量与方程列表。
3. **SymPy 符号验证**（SymPyVerifier）：以符号脚本计算 -∂H/∂x 并与推导结果比对，失败时反馈给推导模块进行最多 3 轮修正；对复杂动力学若超时可跳过验证。
4. **代码生成**（CodeGenerator）：将 PMP 结果生成 C++ 打靶代码，采用固定模板+LLM生成模块的结构。
5. **编译与求解**（SolverRunner）：g++ 编译，链接 cminpack 的 hybrd1 求解器，采用自适应 ε-同伦策略（从 ε=1 连续平滑问题逐步降至 ε=0）。

### 关键技术细节与公式

- **统一哈密顿量**（极小值原理约定）：
  H = λ₀·L + λᵀ·f(x, u, t)
  其中 λ₀ 为异常乘子，L 为运行代价，λ 为协态向量。

- **统一约束框架**：所有约束统一为 ψ(x, p₁, p₂, ...) = 0 形式，处理流程为扫描、分类（状态变量A/乘子B/自由参数C）、生成打靶变量与方程。关键规则：
  - **Rule B**：内部点约束 ψ(x(tₖ))=0 引入乘子 ν，协态跳跃 λ⁺(tₖ) = λ⁻(tₖ) + νᵀ∂ψ/∂x；ν 作为打靶变量，ψ=0 作为打靶方程。
  - **Rule B2**：识别约束中嵌入的自由参数 p（如引力辅助转角 δ、方位角 φ），生成平稳条件 Σₖ νₖ ∂ψₖ/∂p = 0。
  - **Rule G1**：含代价泛函时 λ₀ 必须是打靶变量并参与球面归一化。
  - **Rule G2**：控制方向需验证使 H 最大化或最小化（符号约定取决于采用极大/极小值原理）。
  - **Rule G3**：当最优控制方向 n 依赖状态 x 时，协态方程必须包含几何导数项 ∂n/∂x；包络定理只消去 ∂H/∂α，不消去 ∂n/∂x。
  - **Rule G4**：动力学方程中不出现的量（如太阳帆的质量）不是状态变量，必须排除。

- **自由时间横截条件**：H(tₖ⁻) - H(tₖ⁺) - ν·∂ψ/∂tₖ = 0。

- **四模块代码生成架构**：
  - 标准低推力问题（电推进 bang-bang 控制）只需生成 RESIDUAL 和 SOLVE 模块，DYNAMICS 与 SWITCH 用模板默认。
  - 非标准动力学（太阳帆、J2）需要生成全部四个模块。
  - 太阳帆最优控制律：n = cosα·r̂ + sinα·ŝ，α* = arctan[(-3a + √(9a²+8b²))/(4b)]，其中 a = λ_v·r̂, b = ‖λ_{v⊥}‖。

- **数值稳定性策略**：归一化单位（AU、年）、自由时间用分数 τ∈[0,1] 参数化、目标天体状态在实际到达历元求值、无量纲残差、明确符号约定。

## 7. 优点

- **约束自适应统一框架**：将任意约束统一为 ψ(x,p)=0 形式，自动识别自由参数并生成平稳条件，避免了逐类推导横截条件的繁琐与错误，显著降低人工负担。
- **动力学自适应四模块代码生成**：支持太阳帆、J2 等非标准动力学模型，仅需在问题描述中给出动力学方程，无需修改模板，扩展性强。
- **通用推导规则集**：G1–G4 与 Rule B2 是从 PMP 理论提取的一般性知识而非问题特化提示，可迁移至新问题。
- **符号验证与编译修复闭环**：SymPy 验证失败可反馈修正，编译错误可自动修复，提高系统鲁棒性。
- **数值稳定性设计**：归一化、时间分数参数化、目标历元动态求值、无量纲残差等策略增强了打靶求解的稳定性。
- **全面的实验验证**：11 个递进场景、多模型对比、token 消耗统计、案例深入分析，证据较充分。
- **开源模型选型**：选用的都是公开权重模型，便于复现，且能力跨度大，能揭示规模与能力关系。

## 8. 不足与局限

- **数值收敛瓶颈仍未根本解决**：17 变量以上的场景（如 S10 引力辅助）随机重启策略常超时失败；论文承认 d4 收敛维度包含偶然性，评估可重复性受限。
- **初始猜测策略过于原始**：目前仅使用随机重启，未采用物理信息初值、约简问题延续、近似解热身等更先进技术，这可能是多个场景未收敛的重要原因。
- **SymPy 验证能力有限**：对复杂动力学（如太阳帆）会因表达式爆炸而超时，验证覆盖率约 75%，存在 25% 的错误率，且超时后直接跳过验证，存在推导错误未被发现的风险。
- **LLM 输出非确定性**：同一问题两次运行可能生成略有差异的代码，生产级应用需引入确定性后处理（如检查打靶方程线性独立性）。
- **实验对比不足**：未与传统人工推导的间接法工具、商业求解器或直接法进行对比，难以量化 HELIOS 在效率和解质量上的绝对优势。
- **模型覆盖面有限**：仅测试了 8 个开源模型，未包含 GPT-5、Claude 等专有模型；小模型部分（仅 GLM-4-9B 一个）样本较少，结论的普适性有待加强。
- **算力信息缺失**：未报告推理所用的 GPU 型号、数量、运行总时长等资源消耗，不利于他人评估部署成本。
- **应用场景局限**：尚未覆盖太阳光压、大气阻力、更高保真度引力场等动力学模型，以及更多类型的不等式路径约束。
