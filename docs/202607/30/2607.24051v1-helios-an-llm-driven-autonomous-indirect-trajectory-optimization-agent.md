## 摘要
低推力轨迹优化是深空任务设计的核心技术。基于庞特里亚金最小值原理（PMP）的间接方法提供了严格的最优性保证，但其实际应用面临三个瓶颈：(1) 横截条件必须针对每种约束类型逐一推导；(2) 不同的动力学模型需要重复的代码重写；(3) 打靶方程对初值猜测高度敏感。本文提出了HELIOS（低推力星际优化系统的启发式引擎），一种围绕大语言模型（LLM）构建的轨迹优化智能体。给定一个用自然语言描述的物理问题，该系统自主执行PMP符号推导、SymPy验证、C++打靶代码生成和数值求解，无需人工干预。关键创新包括：(1) 一个约束自适应推导框架，将任意约束统一为psi(x,p)=0形式，并自动生成自由参数（如重力辅助转向角）的平稳性条件；(2) 动力学自适应的四模块代码生成，支持非标准动力学（太阳帆、J2扰动）而无需修改底层模板；(3) 一组通用推导规则集，覆盖PMP推导中关键易错点。在11个递进式测试场景上的实验表明，HELIOS能够正确推导并求解从简单交会（8个变量）到多停留转移（48个变量）、重力辅助轨迹（17个变量）以及太阳帆最短时间转移（8个变量）的问题。最佳编译成功率达到100%（11/11）。一个多模型比较（8个开源LLM后端，总分250-905）验证了与模型无关的架构，并揭示了模型规模与推导能力之间的正相关性。

## Abstract
Low-thrust trajectory optimization is a core technology in deep-space mission design. Indirect methods based on Pontryagin's Minimum Principle (PMP) offer rigorous optimality guarantees, yet their practical application faces three bottlenecks: (1) transversality conditions must be derived case by case for each constraint type; (2) different dynamics models require repeated code rewrites; and (3) shooting equations are highly sensitive to initial guesses. This paper presents HELIOS (Heuristic Engine for Low-thrust Interplanetary Optimization System), a trajectory optimization agent built around a large language model (LLM). Given a physical problem described in natural language, the system autonomously performs PMP symbolic derivation, SymPy verification, C++ shooting-code generation, and numerical solution without human intervention. Key innovations include: (1) a constraint-adaptive derivation framework that unifies arbitrary constraints into psi(x,p)=0 form and automatically generates stationarity conditions for free parameters (e.g., gravity-assist turning angle); (2) dynamics-adaptive four-module code generation supporting non-standard dynamics (solar sail, J2 perturbation) without modifying the underlying template; and (3) a general derivation rule set covering critical error-prone points in PMP derivation. Experiments on 11 progressive test scenarios show that HELIOS correctly derives and solves problems from simple rendezvous (8 variables) to multi-leg stay transfers (48 variables), gravity-assist trajectories (17 variables), and solar-sail minimum-time transfers (8 variables). The best compilation success rate reaches 100% (11/11). A multi-model comparison (8 open-source LLM backends, total scores 250-905) verifies the model-agnostic architecture and reveals a positive correlation between model scale and derivation capability.

## 2. 方法论：核心思想、关键技术细节与算法流程

### 2.1 核心思想
- **LLM驱动自动化**：用户仅用自然语言描述物理问题（目标天体、约束、动力学、参数、目标函数），HELIOS自主完成从问题解析、PMP符号推导、SymPy验证、C++打靶代码生成到数值求解的全部步骤，无需人工干预。
- **通用性设计**：不依赖问题特定的“作弊提示”，而是嵌入从PMP理论提炼的通用推导规则，使系统能自适应处理各类约束和动力学。

### 2.2 关键技术细节

#### 2.2.1 五阶段流水线架构
1. **约束解析（Stage 1）**：将自然语言问题转换为结构化JSON，统一表示所有约束（终端、内点、路径），由LLM在后续阶段决定如何处理。
2. **PMP推导（Stage 2）**：LLM根据问题规范和推导提示，输出完整的间接打靶公式：
   - 哈密顿量（明确最小化原则符号约定）
   - 协态微分方程
   - 最优控制律（bang-bang或连续控制公式）
   - 所有横截条件（终端、内点、自由时间）
   - 打靶变量列表（含物理意义和初值策略）与打靶方程列表（一一对应）
3. **SymPy验证（Stage 3）**：将LLM推导的协态方程与符号微分（-∂H/∂x）对比，最多3轮修正；复杂模型超时时跳过验证。
4. **代码生成（Stage 4）**：根据推导结果生成C++打靶代码，采用**四模块分离架构**（DYNAMICS/SWITCH/RESIDUAL/SOLVE）：
   - 标准低推力问题仅需生成RESIDUAL和SOLVE模块（另两个用模板默认）。
   - 非标准动力学（如太阳帆）需全部四个模块由LLM生成。
5. **编译求解（Stage 5）**：g++编译，链接cminpack的hybrd1求解器，采用**自适应ε-同伦策略**（从ε=1.0逐步下降至0.0），随机重启+同伦下降。

#### 2.2.2 约束自适应推导框架
- 将**所有约束统一为** `ψ(x, p) = 0` 形式，其中 `x` 为状态变量，`p` 为自由参数。
- 处理流程：扫描→分类（A类：状态变量；B类：乘子；C类：自由参数）→生成打靶变量和方程：
  - 每个内点约束引入乘子ν作为变量，约束ψ=0作为方程。
  - 每个自由参数p引入变量和**平稳性方程** `∑ν_k·∂ψ_k/∂p = 0`（规则B2）。
  - 每个自由时间tk引入横截条件方程。
- 示例：重力辅助约束中，自动识别转向角δ和方位角ϕ作为自由参数，无需人工推导特定横截条件。

#### 2.2.3 动力学自适应代码生成
- 通过**四模块架构**区分标准与非标准动力学：
  - 标准低推力：14维状态（7状态+7协态），bang-bang控制，模板提供默认动力学子程序和开关检测积分器。
  - 太阳帆：12维状态（6状态+6协态，无质量），连续锥角控制，LLM生成自定义右端项和最优锥角公式（涉及含余弦三次方程）。
  - J2摄动：在标准模型上加J2加速度项，LLM推导含J2梯度完整3×3雅可比矩阵。

#### 2.2.4 通用推导规则集
- **规则G1**：λ0必须作为打靶变量并参与球面归一化。
- **规则G2**：必须验证最优控制方向（最大化或最小化H）。
- **规则G3**：当最优控制方向依赖于状态（如太阳帆法向量依赖于r方向），协态方程必须包含几何导数项∂n/∂x。
- **规则G4**：不出现在动力学方程中的变量（如太阳帆质量）不视为状态变量。
- **规则B/B2**：内点约束乘子与自由参数处理。
- **规则G5/G6**：禁止推导中使用占位符，J2协态梯度需完整雅可比。

#### 2.2.5 数值稳定性策略
- 归一化（AU, year）；时间用分数τ∈[0,1]表示；目标天体状态用实际历元评估；无因次残差；明确最小化原理符号约定。
